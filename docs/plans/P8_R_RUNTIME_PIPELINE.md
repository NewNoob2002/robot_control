# P8-R — 双轴 PDO 运行管线

日期：2026-09-16。状态：软件范围验收通过；前置 P9.0–P9.3 已验收。最终结果见 [P8-R 基线](../verification/P8_R_RUNTIME_BASELINE.md)。

## 范围和契约

- 复用 CANopen Lifecycle 单 owner、ObservationStore 和 ZLAC 编解码。P6 一次性资格工具及发送门保持独立，不能改成无限运行器。
- 新运行能力为 Debug-only/default-OFF 库，无生产入口、无线遥控入口、线程或自动重连授权。P10 负责仲裁、安全状态与调度编排。
- 采用已验证的 RPDO1：6040:00/16 + 60ff:03/32（6字节）；TPDO1：6041:00/32 + 606c:03/32（8字节）。运行期另需 TPDO2：6061:00/8 + 603f:00/32（5字节）。TPDO2 新布局仅软件验证，需 P10 独立物理验收。
- 创建运行会话必须提供明确的节点、布局读回和 200f=1、同一 transport/boot 代际的验证记录。记录由后续启动 preflight 取得；本节点不伪造实机记录、不改映射、不发送 SDO/NMT。
- 左右目标半字、反馈半字、方向和限幅显式配置；status/fault 保持 low/high 中立名称。历史正向单轮证据不授予负向、双轮或带载资格。
- 在每个接收事件和发送前重新检查模式、fault、心跳/TPDO时效和代际；观察恢复不重新授权。先新授权零目标，再收到新的零速度反馈后才允许后续使能／非零；过期、重放、boot-up、CAN错误、任一轴失效耦合抑制双轴。
- 控制 owner 提交带时间、会话/反馈 epoch 和单调决策序号的 SafetyDecision。运行层不是新的机器人安全权威；不实现自动故障复位。
- 每次发送一个明确的 RPDO，不重试失败发送、不重放缓存目标。Linux 内核延迟 TX 仍未修复，用户态零输出不等于物理停车保证。
