## P9.0–P9.3 细化交付

### P9.0 契约（本次实施）

交付原始证据身份、支持的固定协议、通道与时间配置边界、健康／启停状态规则、
CommandSample 字段约束、独立预期向量和现场未知项。只做只读调查与文档变更，
不创建没有消费者的接口代码。验收：证据可追溯、规则没有隐式运动授权、
边界明确、所有未知项均标出阻塞范围、链接／差异及向量算术检查通过。
该验收是离线契约通过，不是实机接收机通过。

### P9.1 流式解析

交付 `input/sbus/protocol` 的固定存储解析器、原始观察与有序帧／拒绝事件、
统计、CMake 注册和 CTest 用例。复用项目 C++20 与测试框架，不引入第三方协议库。
先实现契约 V01–V06 的独立断言，再实现解析；补充坏尾候选内重同步、
跨 read 截断、长噪声与有界内存检查。不得只向健康层交付最后一帧。
验收依次为窄测试、host Debug/Release、ASan/UBSan、改动范围静态／分层审查、
锁定 cross；不需要物理 CAN。cross 不可用时软件进度单列，完整节点保持待验收。

### P9.2 UART 与只读观察

先核实 SerialPort 的所有调用方，补齐目标速率／格式设置与回读能力；
保持 Linux 机制层无 SBUS 策略。输入 reader 负责有界读取、接收时间、
取消、错误传播、重连会话和残帧／积压处置；观察入口无 CAN 发送依赖。
先通过 PTY 与错误／取消测试，再跑 host/sanitizer/static/cross，
最后在明确设备与访问授权后采集真实接收机，记录配置、原始 bytes 与退出结果。
实际 UART／电平／反相未确认时，不能将 PTY 通过记为 P9.2 完整验收。

### P9.3 健康、映射与快照

交付纯映射／健康逻辑、显式配置校验和不可变 CommandSample 生产者，
复用现有单调时钟与领域类型。先落实 V07–V15，再实现 startup、lost、
recovering、disabled、enabled 语义；独立输入状态不替代机器人安全状态。
测试必须覆盖同 read 中 lost→健康、精确超时、非中立零输出、按钮冷却、
未释放按钮、重连及代际溢出。先运行纯逻辑测试，再 PTY→解析→快照组合回归，
host/sanitizer/static/cross；以已确认 profile 完成真实输入无运动验收。
真实采集已观察到启动碎片、合并帧和重同步拒绝；P9.3 须覆盖这些启动输入，
不能仅靠同批连续帧数量推断发射机新鲜度或运动授权。
纯 SBUS 中立授权到安全层的衔接保留给 P10，不能通过伪造 external 输入解决。

## 每个节点的统一提交与验收流程

1. 开始时固定需求、配置、前置节点和预期结果。安全／仲裁语义变化先更新测试。
2. 在当前开发分支按节点提交代码、英文 Doxygen、相关测试和简短验证记录并 push；
   不预建所有未来分支，也不提前填 PASS。每个节点应能单独审查和回归。
3. 先跑最窄变更测试，再跑适用 host 构建／CTest、ASan/UBSan、现有 CI 静态检查、
   锁定工具链和真实目标 sysroot 的 cross／ELF 检查。涉及 CAN 时增加 managed vcan；
   仅解析／映射节点不要求无关 CAN HIL。具体新增测试名随实现注册，不能声称已有。
4. 需要物理证据的节点，在软件通过后单独执行目标 smoke／HIL。固定二进制哈希、
   配置、运行期限、刺激、停止期限、捕获完整性和最终处置；缺少目标或授权时标记待验收。
5. 记录命令、退出码、测试数、skip、日志／捕获路径、源码和二进制身份、
   操作员确认及未验证项。软件通过与硬件通过分列，故障和无效试验保留。
6. 相关检查通过后停止重复测试。节点通过才推进其依赖项；并行离线工作可以继续。

## 本轮边界及后续工作

本次分支准备交付为开发分支和计划；后续实现范围为 P9 SBUS、P8-R 运行管线补齐和 P10 整链。分支创建及计划确认不构成硬件操作授权。
尚未确认的接收机／接线信息应在 P9.0 收集，不通过猜测填入配置。
当前物理电源状态以时间戳记录和操作员现场确认为准。

本阶段的 M4 Bench 含义限于 SBUS 到驱动的受限台架整链能力，不能视为完成生产系统。
ROS2 适配、生产 daemon／systemd 生命周期、带载测试和生产部署另立里程碑；
ROS2 只提交时间戳命令样本，不能拥有安全或驱动生命周期。
任何物理试验均需新的明确授权，旧归档 runner／授权不得复用。
